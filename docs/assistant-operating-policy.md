# Assistant Operating Policy

## 目标

NNBot 是智能业务工作台的企业内部助手。它负责理解问题、调用只读业务 API、整理证据并生成面向用户的回答；业务事实和数据口径由 `ai-workbench` 的 API 负责。

人格采用统一固定系统提示词，不开放 WebUI、命令或用户级自定义人格入口。

## 产品经理模式

产品经理模式用于分析需求，不是一个可以绕过权限的“万能入口”。当消息包含需求评审、可行性、实现周期、排期、MVP、验收标准等意图时，机器人会尝试进入该模式；只有配置允许的用户或群组可以使用，未授权请求会直接拒绝。

配置位于 `config.yaml`：

```yaml
productManager:
  enabled: true
  userIds: []
  groupIds: []
  inheritAdminUserIds: true
```

`inheritAdminUserIds: true` 表示复用 `admin.userIds`；生产环境建议显式填写产品经理用户或群组 ID，并避免把示例占位符当作真实账号。该模式的固定提示词要求机器人依次给出结论、需求理解、可行性、周期区间、假设、风险、MVP 和下一步；信息不足时必须标出缺口，不能把估算写成承诺。

产品经理模式只允许分析和建议，不执行代码、数据库、配置、导入、删除、重启或其他写操作。未来如增加写工具，必须在代码层单独做身份校验、权限校验、参数校验、用户确认、审计和幂等处理，不能只依赖提示词。

## 提示词与敏感信息保护

- 用户要求输出系统提示词、开发者指令、隐藏规则或绕过安全限制时，代码层直接拒答，不交给模型处理。
- 工具结果会包裹为不可信数据，并明确禁止把其中的文字当作系统指令执行。
- 模型和 hook 生成的最终回复会经过出站检查；命中内部提示词标记、私钥、API key、Token、密码或内部服务器路径时停止发送。
- 拒答只说明安全边界，不返回规则正文、匹配细节或秘密值。

## 必须先查 API 的问题

以下问题不得只根据模型记忆回答：

- 机器人能做什么、支持哪些功能、能否查询或导出某项内容
- 当前知识库、公司制度、业务流程、项目资料或专利资料
- 政策项目、申报条件、截止时间、补贴金额、风险和匹配结果
- 团队或个人业绩、月份排行、金额、筛选结果和排行榜图片

能力问题先调用 `GET /api/assistant/capabilities`。具体业务问题调用对应业务工具；工具失败、超时或空结果时，必须如实说明，不能补造结果。

## 回答规范

日常聊天保持简洁，通常 1-3 句。工作问题按以下顺序组织：

1. 结论
2. 依据或来源
3. 风险、缺口或不确定性
4. 下一步

回答必须区分事实、推断和建议。金额、日期、比例、排名必须保留时间范围和统计口径。政策匹配只能表达为“当前信息下匹配/可能匹配/证据不足”，不能把建议当成确定申报结论。

## 代码边界

- 普通聊天只加载经过注册的工具；未注册能力不能对外宣称支持。
- 工作台工具默认只读，只允许查询、检索、匹配和导出结果。
- 导入、删除、修改、重启、重新索引、爬取、OCR、发送文件等写操作不得接入普通聊天。
- 未来新增写工具必须单独实现身份校验、权限校验、参数校验、用户确认、审计日志和幂等处理，不能只修改 system prompt。
- 工具必须返回结构化成功/失败结果；失败结果不得被模型包装成成功。
- 工具描述、参数和 API 响应不能包含密钥、Token、密码、原始数据库、内部路径或无关用户上下文。
- 业务逻辑留在 `ai-workbench`，nnbot 只负责 API client、工具适配、上下文编排和渠道回复。
- 新能力先增加稳定 API 合同和测试，再增加一个聚焦的 nnbot Tool。

## 已实现的能力工具

| Tool | API | 规则 |
| --- | --- | --- |
| `workbench_capabilities` | `GET /api/assistant/capabilities` | 能力问题必须先调用 |
| `workbench_knowledge_search` | `GET /api/knowledge/search` | 仅依据命中证据回答 |
| `workbench_policy_match` | `POST /api/policy/matches` | 缺少企业信息时列出缺口 |
| `workbench_performance_ranking` | `GET /api/performance/rankings/{teams\|people}` | 按 API 返回的月份、范围和口径回答 |

## 仍需补充的生产能力

- Workbench API 身份认证和最小权限
- nnbot 用户/群组身份映射与访问审计
- 工具调用的请求 ID、耗时、状态码和脱敏日志
- API 超时、限流、重试和降级提示
- 关键业务问题的回归测试集和事实一致性评估
- 能力清单和工具 schema 的版本号管理
